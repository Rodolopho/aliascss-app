# Screens and other Block level  Wrappers 

AliasCSS uses **scope wrapper prefixes** for media queries, layers, container queries, and other block-level CSS wrappers.

A scope wrapper prefix does not behave like a normal utility prefix. Instead, it creates an outer CSS block such as `@media`, `@layer`, `@container`, or `@starting-style`. Because of that, AliasCSS parses scope wrappers before selectors, states, properties, and values.

---

## Quick start

### Single scope wrapper

```html
<div class="@md-d-flex"></div>
<div class="@base-d-flex"></div>
<div class="@container-md-grid-template-columns-2"></div>
<div class="@dark-c-white"></div>
```

### Grouped scope wrappers

```html
<div class="@[md,base]-d-flex"></div>
<div class="@[container-md,base]-grid-template-columns-2"></div>
<div class="@[md,container-md][d-flex,gap-16px]"></div>
```

<Callout type="info" emoji="💡">
For consistency, prefer the `@` form for single scope wrappers. It makes it obvious that the prefix creates a CSS wrapper block.
</Callout>

---

## Core rule

A scope wrapper can be used in two ways:

### 1. Single scope wrapper

```text
@scope-utility
```

Examples:

```html
<div class="@md-d-flex"></div>
<div class="@base-d-flex"></div>
<div class="@container-md-grid-template-columns-2"></div>
<div class="@motion-reduce-an-none"></div>
```

### 2. Grouped scope wrappers

```text
@[scope,scope,scope]-utility
@[scope,scope,scope][utility,utility]
```

Examples:

```html
<div class="@[md,base]-d-flex"></div>
<div class="@[container-md,base]-grid-template-columns-2"></div>
<div class="@[dark,base][c-white,bgc-black]"></div>
```

<Callout type="warning" emoji="⚠️">
If a class needs more than one scope wrapper, group them with `@[...]`. Do not chain multiple scope wrappers as plain prefixes.
</Callout>

---

## Why `@` is recommended

Every scope wrapper prefix is conceptually a block wrapper. The `@` marker makes that meaning visible in the class name.

### Recommended

```html
<div class="@md-d-flex"></div>
<div class="@xs-dn"></div>
<div class="@dark-c-white"></div>
<div class="@container-md-grid-template-columns-2"></div>
```

### Also valid for selected common scopes

```html
<div class="md-d-flex"></div>
<div class="xs-dn"></div>
<div class="dark-c-white"></div>
<div class="print-display-none"></div>
```

AliasCSS currently supports **a limited set of popular scope wrappers without `@`** for convenience. However, the recommended style is still to use `@` because it clearly signals a scope wrapper.

<Callout type="info" emoji="ℹ️">
Not every scope wrapper currently has a no-`@` alias. The `@` form is the complete and future-friendly form.
</Callout>

---

## Important grouped syntax rule

Inside `@[...]`, use **bare scope keys**.

### Correct

```html
<div class="@[md,base]-d-flex"></div>
<div class="@[container-md,base]-grid-template-columns-2"></div>
<div class="@[dark,md][c-white,bgc-black]"></div>
```

### Incorrect

```html
<div class="@[md,@base]-d-flex"></div>
<div class="[@container-md,base]-grid-template-columns-2"></div>
<div class="[@dark,md][c-white,bgc-black]"></div>
```

Why? Because inside `@[...]`, AliasCSS is already parsing a scope list. Each item is treated as a scope key, so the extra `@` is unnecessary.

---

## Order and precedence

The order inside `@[...]` matters.

AliasCSS reads scope keys from left to right. That order determines how the generated CSS blocks are nested.

### Example

```html
<div class="@[md,base]-d-flex"></div>
```

Conceptual output:

```css
@media (min-width: 768px) {
  @layer base {
    .class {
      display: flex;
    }
  }
}
```

### Reversed order

```html
<div class="@[base,md]-d-flex"></div>
```

Conceptual output:

```css
@layer base {
  @media (min-width: 768px) {
    .class {
      display: flex;
    }
  }
}
```

### Rule

```text
The order inside @[...] determines scope precedence.
```

That means:

1. the left-most scope wraps first
2. the next scope nests inside it
3. the final utility is generated in the deepest scope

---

## Grammar order

Scope wrappers are parsed before the rest of the class.

### Basic grammar

```text
@[scope,scope,scope] → selector/state → property → value
```

### With grouped utilities

```text
@[scope,scope,scope][utility,utility,utility]
```

### Mental model

1. Resolve scope wrappers.
2. Resolve selectors and states.
3. Resolve property and value.
4. Emit the CSS declaration inside the nested wrapper blocks.

---

## Scope wrappers vs selectors

A scope wrapper is not the same thing as a selector or pseudo state.

### Scope wrappers

- `md`
- `xs`
- `dark`
- `base`
- `container-md`
- `motion-reduce`
- `starting-style`

### Selectors and states

- `_p`
- `_div`
- `--hover`
- `--focus`
- `[data-state=open]`

### Example

```html
<div class="@[md,base]_p-c-red"></div>
```

Mental model:

- `@[md,base]` creates the wrapper blocks
- `_p` targets the `p` selector inside those blocks
- `c-red` defines the final declaration

### Single responsive scope

```html
<div class="@md-w-500px"></div>
<div class="md-w-500px"></div>
```

Compiled idea:

```css
@media (min-width: 768px) {
  .class {
    width: 500px;
  }
}
```

```html
<div class="@base-d-flex"></div>
```

```css

  .class {
    display: flex;
  }
```


## Best practices

- Prefer the `@` form for single scope wrappers.
- Use no-`@` aliases only when you intentionally want shorter syntax.
- When combining multiple scopes, always use `@[...]`.
- Inside `@[...]`, use bare scope keys.
- Keep scope order intentional, because order changes nesting precedence.
- Do not place selectors such as `_p` or states such as `--hover` inside the scope list.
- Use grouped utilities when several declarations share the same wrapper structure.

---

## Common pitfalls

- Writing `@[md,@base]` instead of `@[md,base]`
- Assuming `@[md,base]` is the same as `@[base,md]`
- Mixing selectors into the scope list
- Chaining multiple scope wrappers without `@[...]`
- Assuming every scope wrapper currently has a no-`@` alias

---

## Cheat sheet

```text
@md-d-flex
-> one media scope

md-d-flex
-> same as @md-d-flex (supported convenience alias)

@base-d-flex
-> one layer scope

@container-md-grid-template-columns-2
-> one container scope

@[md,base]-d-flex
-> media scope, then layer scope

@[container-md,base]-grid-template-columns-2
-> container scope, then layer scope

@[md,container-md][d-flex,gap-16px]
-> media + container with grouped utilities
```
